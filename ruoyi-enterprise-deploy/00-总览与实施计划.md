### 2.4 访问方式替代方案（不备案、不买证书）

```bash
# 1) 用 nip.io 通配域名指向你的 EIP（无需买域名/备案），Ingress 的 host 写 ruoyi.<EIP>.nip.io
kubectl -n ruoyi-prod get svc ruoyi-nginx          # 先确认服务存在
# 2) 或者本机 hosts 绑定（Windows: C:\Windows\System32\drivers\etc\hosts）
#    <EIP>  ruoyi.lab.local

# 3) TLS 用自签证书（浏览器会警告，属正常）
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout lab.key -out lab.crt -subj "/CN=ruoyi.lab.local" \
  -addext "subjectAltName=DNS:ruoyi.lab.local"
kubectl -n ruoyi-prod create secret tls ruoyi-lab-tls --cert=lab.crt --key=lab.key

# 4) 所有管控台统一用 port-forward 访问，不暴露公网（Service 名以 kubectl get svc -n <ns> 实际输出为准）
kubectl -n ruoyi-middleware port-forward svc/ruoyi-nacos 8848:8848                     # Nacos 控制台
kubectl -n ruoyi-middleware port-forward svc/ruoyi-sentinel-dashboard 18858:8858       # Sentinel
kubectl -n ruoyi-monitoring port-forward svc/ruoyi-skywalking-ui 18082:8080            # SkyWalking UI
kubectl -n ruoyi-logging    port-forward svc/ruoyi-kibana 15601:5601                   # Kibana
kubectl -n ruoyi-monitoring port-forward svc/kube-prometheus-stack-grafana 13000:80    # Grafana
kubectl -n ruoyi-monitoring port-forward svc/kube-prometheus-stack-prometheus 19090:9090 # Prometheus
```

**不买 SLB/WAF**：直接用节点 EIP + Nginx Ingress（`hostNetwork` 或 NodePort 方式由 `02` 第 5 章给出）。

### 2.7 学习环境的"现象差异"速查（避免把正常现象当故障）

| 你在文档里看到的（生产） | 学习环境实际表现 | 为什么正常 |
| --- | --- | --- |
| 滚动更新业务无感 | **会有几十秒 502** | 只有 1 副本，旧 Pod 停了新 Pod 还没就绪 |
| 删 Pod 用户无感 | **会短暂中断** | 单副本无冗余；想练零中断可临时 `kubectl scale --replicas=2` |
| Nacos 3 节点、能抗 1 节点故障 | 重启 Nacos 期间所有服务心跳失败、配置读不到 | standalone 无集群；这本身是必学场景 |
| ES 3 节点、副本分片 | 只能 green（副本 0）或 yellow/red | 单节点不能存副本分片 |
| RDS 主备自动切换 | 无此场景 | 集群内单实例 MySQL |
| 云监控/SLS/ARMS 排障 | 改用 Prometheus/Grafana/Kibana/`kubectl` | 学习环境不接云产品 |
| Prometheus/Kibana 双副本 | 重启期间监控页面短暂打不开 | 单副本 |
| `drain` 节点 Pod 自动迁移 | 只有 3 节点，可能卡 `Pending` | 先加第二台或先 `uncordon` 再练 |

### 3.7 时间不够时的裁剪顺序

**先砍**（影响最小）：JMeter 压测 → Grafana 大盘美化 → ES snapshot 到 OSS → 跨可用区实验 → Helm Chart 化（直接用 YAML 也能跑）。

**绝对不能砍**：命名空间与标签规范、探针三件套、Nacos 注册与配置、gateway 路由打通、一次回滚、一次备份恢复、2–3 个故障演练。

## 8. 资源释放与防扣费（学完当天必须做）

**释放前先留存**：镜像 tar、YAML/Helm Chart、Nacos 配置导出、MySQL 备份文件、关键截图与上面的总结文档——这样以后想在本地 kind/k3s 复现时不用重来。

## 9. 学习环境专属 10 个坑

| # | 坑 | 怎么避免 |
| --- | --- | --- |
| 1 | 忘记释放按量资源，账单持续增长 | 学习当天就按第 8 章执行；设一个手机提醒 |
| 2 | 把集群 EIP 直接暴露 Nacos/Kibana 到公网 | 管控台只用 port-forward；安全组最小放通 |
| 3 | 单副本时做滚动更新，看到 502 以为部署失败 | 那是预期现象（第 2.7 节），要零中断先 `scale --replicas=2` |
| 4 | ES 单节点却把索引副本设为 1，集群永远 yellow | 单节点索引副本数必须为 0 |
| 5 | 节点盘 60GiB 被镜像与日志写满 | 调低 kubelet 镜像回收阈值；容器日志轮转；ES 数据盘独立 |
| 6 | `drain` 唯一有 Pod 的节点，Pod 卡 Pending | 先加第二台节点，或 `--ignore-daemonsets --delete-emptydir-data` 并接受中断 |
| 7 | 用 `.yaml` 后缀发布而应用按 `yml` 读配置，配置"不生效" | 前后缀统一为 `.yml`（与 `file-extension: yml` 一致） |
| 8 | JVM 堆按 `limits` 配满，Pod 反复 OOMKilled | 记住 `XMX ≤ 0.75×limits`，`XMS = requests` |
| 9 | ACR 个人版与企业版镜像地址混用导致拉取失败 | 统一用个人版地址：`registry.cn-hangzhou.aliyuncs.com/<你的命名空间>/...` |
| 10 | 自签证书/ nip.io 打不开就以为 Ingress 配错 | 先 `kubectl describe ingress` 看后端与事件，再用 `curl -k` 从集群内测服务本身 |
